# 这份备赛积累怎样保留

2026 年备赛后的资料分成两个入口：[2026-Ti](https://github.com/liusuan110/2026-Ti) 保存训练与选型过程中的积累，[ti-last](https://github.com/liusuan110/ti-last) 保存 F题完整工程与方案说明。前者方便找例程、看旧题和复用模块，后者方便重建一个具体项目。

## 保留工程路径，用阅读路线连接资料

原有工程和资料沿用原路径，首页与[资产索引](ASSET_INDEX.md)按学习任务组织入口。这样，读者既能沿“采集—分析—输出”理解系统，也能继续从工程中打开源码、配置和手册。

H题的 H_SignalSep 与 SignalSeparator_v2 分别保留。前者保存模块化设计和离板测试，后者记录后续开发与接线变化。它们共同反映训练过程，各自的说明记录对应版本。

F题早期报告也留在本库，用来回看从线性 CCD 一维采样到 UVC 摄像头方案的变化。它保存了当时的观测思路、DDS 时钟假设和待补实验内容，可以与 [ti-last 的报告](https://github.com/liusuan110/ti-last/tree/main/F%E9%A2%98%E8%AE%BE%E8%AE%A1%E6%8A%A5%E5%91%8A) 对照阅读。

## 让后续记录接得上

工程表中的“空工程、方案、编译记录、离板测试、原作者演示”说明资料保留到哪一步。继续开发时，在原有记录后追加日期、源码提交、工具与硬件配置，再写测试数据和结论。

赛前分析与每日状态保留原日期；选型时重新查看器件规格、价格和供货。题目、厂商手册和参考工程保留原作者、来源与许可证信息，具体授权见各目录说明。

文档先讲清它解决的问题和阅读顺序，再给必要的操作细节。工程状态集中放在索引和实验记录里，避免在各篇开头反复打断读者。
